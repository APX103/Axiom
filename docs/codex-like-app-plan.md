# 做一个"长得像 Codex"的本地 APP：方案说明

> 写给不太熟悉前端/桌面开发的人看。尽量不用黑话，把每一步讲清楚。

## 一、先搞清楚你要做的东西到底是什么

你说的"Codex"，目前市面上大家通常指的是 **OpenAI 的 Codex 系列产品**：

- **网页版 / 桌面版**：一个聊天窗口，左边可以传文件、看项目文件树，中间是聊天记录，底部是输入框，AI 会一边思考一边调用工具（读文件、写代码、运行命令）。
- **CLI 版**：在终端里用，不太像普通 APP。

你老板想要的是**前者**：一个长得像 ChatGPT/Codex 桌面客户端的**本地工具**，能在自己电脑上跑，不用依赖网页。

这个项目现在的情况是：

- 后端：Python（FastAPI），已经能跑 agent、能对话、能操作文件。
- 前端：已经有一个网页版工作台（React + TypeScript + Tailwind + Vite）。

所以问题其实不是"从零做一个 APP"，而是：**怎么把现在这套网页版，打包成一个像 Codex 一样的本地桌面 APP**。

---

## 二、做桌面 APP 有哪几条路？

做本地 GUI 工具，现在主流有三条路。我按"像不像 Codex"、"好不好做"、"体积小不小"给你对比。

| 方案 | 通俗解释 | 优点 | 缺点 | 像 Codex 的程度 |
|---|---|---|---|---|
| **A. Tauri（推荐）** | 用 Rust 写一个很小的"壳"，里面嵌一个浏览器窗口跑你的 React 页面。 | 包体很小（十几 MB）、启动快、原生能力强（文件菜单、托盘、通知）。 | 壳是 Rust 写的，前端还是 React，需要多学一点 Rust 壳配置。 | ⭐⭐⭐⭐⭐ |
| **B. Electron** | 把整个 Chromium 浏览器一起打包进去，跑你的 React 页面。 | 最成熟、文档最多、前端最自由。 | 包体巨大（100MB+）、内存占用高。 | ⭐⭐⭐⭐⭐ |
| **C. 纯 Bun 打包成可执行文件** | 用 `bun build --compile` 把 TS 代码打包成一个命令行程序。 | 包体小、一个文件。 | **没有 GUI**，只能跑命令行，做不出窗口界面。 | ⭐ |

> 你说的"用 JS/TS 写、用 bun 打包"，如果目标是**有窗口的 APP**，那 bun 只能负责"构建前端代码"和"跑脚本"，真正的桌面壳必须靠 Tauri 或 Electron。
>
> 换句话说：**bun 是菜刀，Tauri/Electron 是厨房**——两者不是互相替代，而是分工合作。

## 三、推荐方案：Tauri + 现有 React 前端 + 内嵌 Python 后端

### 3.1 整体架构（一句话版）

```
┌─────────────────────────────────────┐
│  用户看到的桌面窗口（Tauri 壳）        │
│  ┌───────────────────────────────┐  │
│  │  React 页面（聊天、文件树、输入框）│  │
│  │  用 TypeScript + Tailwind 写    │  │
│  └───────────────────────────────┘  │
│           ↑↓ 通过 HTTP/WebSocket 通信  │
│  内嵌 Python 后端（FastAPI）          │
│  负责：LLM、Agent、文件操作、工具调用   │
└─────────────────────────────────────┘
```

### 3.2 为什么推荐 Tauri？

1. **包小**：Electron 打包后通常 150MB+，Tauri 通常 15~40MB。
2. **够用**：你现在的前端就是网页，Tauri 可以直接把它包进去。
3. **安全**：Tauri 默认前端不能随便访问本地文件，必须通过 Rust 端显式暴露接口。
4. **像 Codex**：Codex 桌面客户端本身也是这种"壳 + 网页"结构。

### 3.3 各部分分别做什么？

| 部分 | 现在有没有 | 要做什么改动 | 用什么技术 |
|---|---|---|---|
| 前端界面 | ✅ 已经有了 | 改成更像 Codex 的界面（下面会讲） | React + TypeScript + Tailwind + Vite |
| 桌面壳 | ❌ 没有 | 新建一个 Tauri 项目，把前端包进去 | Tauri（Rust 配置） |
| 后端服务 | ✅ 已经有了 | 启动时由 Tauri 自动拉起来 | Python FastAPI |
| 通信 | ✅ 已经有了 | 前端直接调用现有 API | HTTP + WebSocket |

### 3.4 启动流程

1. 用户双击打开 APP。
2. Tauri 壳先启动，同时后台起一个 Python 进程（`axiom serve`）。
3. 等 Python 后端启动成功后，打开窗口。
4. 窗口里加载 React 页面，页面自动连接 `http://127.0.0.1:8000`。
5. 用户看到的就是一个长得像 Codex 的本地工具。

## 四、界面怎么改成"像 Codex"？

你现在的前端长这样：

- 左栏：会话列表
- 中栏：聊天记录
- 右栏：工作区 + 计划

Codex 的界面更接近一个**聊天式 IDE**：

```
┌─────────────────────────────────────────────────────────────┐
│  顶部：项目名称 / 当前模型 / 设置图标                           │
├─────────┬──────────────────────────────────────────┬────────┤
│         │                                          │        │
│  文件树  │           聊天记录（流式输出）             │  工具  │
│  /项目   │           AI 写的代码、思考过程           │  结果  │
│  目录    │                                          │  面板  │
│         │                                          │        │
│         │  ┌────────────────────────────────────┐  │        │
│         │  │ 输入框 + 附件按钮 + 发送按钮         │  │        │
│         │  └────────────────────────────────────┘  │        │
├─────────┴──────────────────────────────────────────┴────────┤
│  底部：token 用量 / 当前状态 / 快捷操作                        │
└─────────────────────────────────────────────────────────────┘
```

### 4.1 具体要改哪些 UI？

| 现在 | Codex 风格 | 改动量 |
|---|---|---|
| 左侧会话列表 | 左侧项目文件树 | 中等 |
| 中间只是聊天 | 聊天 + 代码块高亮 + 文件 diff | 中等 |
| 右侧工作区/计划 | 右侧工具结果/运行日志 | 小 |
| 顶部简单标题 | 顶部命令栏（模型选择、设置、新建会话） | 小 |
| 输入框在底部 | 底部悬浮输入框 + 附件/图片上传 | 小 |

### 4.2 颜色风格

Codex 用的是深色主题（接近 GitHub Copilot Chat / ChatGPT 桌面版）：

- 背景：深灰/近黑（`#0d1117`、`#1e1e1e`）
- 用户气泡：深色/蓝色
- AI 气泡：浅灰或半透明
- 代码块：带语法高亮
- 强调色：OpenAI 绿/蓝

你现在前端是浅色（灰白色），要改成深色主题，基本就是把 Tailwind 的颜色类换一遍。

## 五、实现步骤（按顺序做）

### 第 0 步：确认方向

先回答三个问题：

1. **要不要做真正的桌面 APP？** 还是网页版就够了？
2. **能不能接受 Rust 壳？** 其实不需要写很多 Rust，主要是配置文件。
3. **要不要深色主题？** 这是"像 Codex"最关键的视觉元素。

### 第 1 步：把现有前端改成 Codex 风格

这是最快出效果的一步：

1. 把 `App.tsx` 的浅色背景改成深色。
2. 左侧从"会话列表"改成"项目文件树"（可以先用假数据）。
3. 中间聊天记录加入代码高亮（已经装了 `react-markdown`，再加 `prismjs` 或 `shiki` 即可）。
4. 底部输入框做成悬浮卡片样式。
5. 顶部加模型选择、设置按钮、新建会话按钮。

### 第 2 步：接入 Tauri 桌面壳

1. 在 `frontend/` 目录里加 Tauri 配置（`tauri.conf.json`）。
2. 写一个启动脚本，让 Tauri 启动时自动拉起 Python 后端。
3. 打包测试：看能不能双击打开一个窗口。

### 第 3 步：把 Python 后端打包进去

1. 用 `pyinstaller` 把 Python 后端打包成单个可执行文件。
2. Tauri 启动时调用这个可执行文件。
3. 关闭 APP 时，Tauri 也要把 Python 进程一起杀掉。

### 第 4 步：完善本地功能

1. 文件树能真正读取本地目录。
2. 能把文件拖进输入框作为附件。
3. 能把 AI 生成的代码一键写入本地文件。
4. 加入系统托盘、开机启动等（可选）。

## 六、关于 bun 的真实角色

你说的"用 bun 打包"，在这个方案里 bun 可以做：

| 用途 | 能不能做 | 说明 |
|---|---|---|
| 前端开发服务器 | ✅ | `bun run dev` 替代 `npm run dev`，启动更快 |
| 前端构建 | ✅ | `bun run build` 替代 `vite build` |
| 前端依赖安装 | ✅ | `bun install` 替代 `npm install` |
| 打包前端资源 | ✅ | 生成 `frontend/dist` |
| 打包成桌面 APP | ❌ 单独不行 | 需要 Tauri/Electron 提供桌面壳 |
| 打包 Python 后端 | ❌ | Python 后端用 pyinstaller |

所以 bun 是"加速工具"，不是"万能打包工具"。

| 问题 | 选项 A | 选项 B | 我的建议 |

## 八、大概工作量

| 阶段 | 人天（一个人做） | 产出 |
|---|---|---|
| 前端改深色 + Codex 布局 | 2~3 天 | 能看的界面 |
| 接入 Tauri 壳 | 1~2 天 | 能双击打开的窗口 |
| Python 后端内嵌打包 | 1~2 天 | 用户不需要装 Python |
| 文件树、附件、代码写入等完善 | 3~5 天 | 真正的本地工具 |
| 测试 + 打包 Mac/Windows | 2~3 天 | 可分发安装包 |

**总计：大约 1~2 周能出一个可用的 demo，1 个月左右能做比较完整。**

## 九、下一步建议

如果你同意这个方向，我建议按这个顺序推进：

1. **先只做前端改版**：把现有 `frontend/src/App.tsx` 改成深色 Codex 风格，用 `npm run dev` 或 `bun run dev` 预览。
2. **看到效果后再包桌面壳**：前端满意了，再接 Tauri。
3. **最后处理 Python 打包**：这是工程活，不影响界面效果。

这样每一步都有可见成果，老板也能尽早看到东西。

## 十、术语小词典

| 术语 | 一句话解释 |
|---|---|
| **Tauri** | 一个工具，能把网页打包成很小的桌面 APP。 |
| **Electron** | 另一个工具，也能把网页打包成桌面 APP，但体积大很多。 |
| **React** | 一种写网页界面的方式，你现在前端已经用了。 |
| **TypeScript** | JavaScript 的"升级版"，带类型检查，减少 bug。 |
| **Vite** | 开发时帮你把代码跑起来的工具。 |
| **bun** | 一个很快的 JS 工具，能跑脚本、安装依赖、打包代码。 |
| **Tailwind** | 一种写 CSS 样式的方法，通过类名直接控制外观。 |
| **WebSocket** | 前端和后端之间实时双向通信的通道。 |
| **FastAPI** | 项目现在后端的 Python 框架，提供 API 接口。 |
| **PyInstaller** | 把 Python 程序打包成独立可执行文件的工具。 |
