# Claim Verification, Not Evidence Audit

> AI 时代科研验证的本质：从"PI 审阅"到"可数学化的验证层 + 显式价值函数"
>
> 起因：调研 SciForge 的 Evidence DAG 后，对"科研正确性如何保证"这个本质问题的思考。
> 本文不是技术方案，是立场文档（position doc）。落地架构在最后给出方向。

---

## 0. TL;DR

- **PI 作为"正确性保证者"是虚构的**——人类 PI 也保证不了正确性，replication crisis 证明了这点。
- **PI 作为"价值函数定义者"是真实的、不可替代的**——"什么值得做"永远是价值选择。
- **科研可数学化的验证（大概 60-70%）人类科学根本没真做**——这是 AI 时代的巨大机会。
- **剩下 30-40% 是结构性不可数学化的**（品味、意义、隐藏假设），需要外部判断——但"外部判断"不等于"PI 审阅"。
- **SciForge Evidence DAG 的本质问题：它在审计过去，不在规划未来。它解决"合规"，不解决"进步"。**

---

## 1. PI 是不是必须的节点

**是必须的，但不是因为我们以为的原因。**

直觉认为"PI 必须看，是因为 PI 有专业眼光能判断对错"。这个直觉一半对一半错。PI 真正在做的事，分解开来是四个不同功能：

| 功能 | 本质 | AI 能不能替代 |
|---|---|---|
| **先验** | 知道哪些问题值得问、哪些方向是死胡同 | 部分能（基于历史数据），但"值不值得"是价值判断 |
| **品味** | 知道什么是好答案、什么是平庸答案 | 不能（品味是社会化训练的产物） |
| **纠错** | 从外部视角看出学生自己看不到的错 | 能，但需要多个独立视角 |
| **社会资本** | 署名、推荐、让工作被看见 | 完全不需要（AI 不需要 tenure） |

学生看不到自己 survey 的问题，**不是因为认知水平低，是因为他在系统内部**。这是结构性问题：你写出来的东西，你的大脑已经认为它是对的（否则不会写出来），所以检查时大脑会自动跳过那些"已经认为对"的地方。这就是为什么学生"自己检查一遍还是那样"——不是不努力，是认知循环。

PI 能看到，**不是因为 PI 更聪明，是因为 PI 是外部视角**。换个 PI 也能看到大部分问题。换十个独立 reviewer 也能看到。

> **这里 PI 不可替代的不是"判断力"，是"外部性"。**

这条结论直接告诉你 AI 时代怎么做：**不需要复刻一个超级 PI，需要的是制造外部性**——多个独立 agent、不同 prior、互相挑刺。这正是 SciForge 的 A2 (adversarial reviewer) 想做但没做透的方向。

## 2. PI 也会错——那科学到底怎么保证正确性

一个不舒服的事实：

> **科学界从来没有"正确性保证"。它只有"暂时没有人证明它错"。**

具体的纠错机制只有四个，而且都很弱：

1. **复现**——金标准，但实际很少有人做。Replication crisis：生物、心理、医学领域 50%-70% 的发表结果独立复现不出来。这不是 AI 时代的问题，是人类科学几十年来的状态。
2. **时间**——错误的结论会被慢慢淘汰。但"慢慢"是真的慢，十年起步。冷聚变 1989 年提出，花了五年才被否定；阿尔茨海默症淀粉样蛋白假说主导了 30 年，2022 年才发现关键论文造假。
3. **理论一致性**——和已知的东西对得上吗？但"已知的东西"也是这么来的，循环风险。
4. **反常积累 → 危机**——Kuhn 说的范式转换。要等错误多到一个领域无法忽视，往往需要一代人退休。

**PI 犯错怎么办？答案是：经常没人发现，发现了也很慢。** 著名 PI 发的错论文可以主导一个领域几十年。这不是 bug，这是科学作为人类活动的结构性特征。

人类科学的"严谨"在很大程度上是**仪式性的**——peer review 听起来很严格，实际上 reviewer 平均花 4 小时审一篇论文，主要看 narrative 是否流畅、引用是否得体、方法是否"看起来"合理。Reviewer 不会重跑实验、不会重算统计、不会查每条引用的真伪。

> **人类科学的"严谨"主要靠信任，不靠验证。**

所以"怎么保证正确性"的诚实答案是：**人类科学从来没真正保证过**。它只保证"过了几道社会关"，跟数学证明那种确定性完全不是一回事。

## 3. 能不能数学化、符号化、确定性

### 3.1 可以数学化的部分（大概 60-70%）

| 验证类型 | 能做到什么 | 工具 |
|---|---|---|
| **逻辑一致性** | 前提 A、B、C 是否蕴含结论 D？矛盾吗？ | 形式逻辑、定理证明器（Coq、Lean） |
| **可复现性** | 给定代码+数据+参数+环境+seed，能跑出同样结果吗？ | 容器化、content-addressed artifact |
| **统计有效性** | p-value、置信区间、贝叶斯后验，是否算对了？ | 统计校验、pre-registration |
| **证据依赖** | 这个结论依赖哪些证据？依赖的证据成立吗？ | 依赖图、因果图 |
| **来源真实性** | 引用的论文真的说了这话吗？DOI 真实吗？ | 内容寻址、签名、anchor |

这五项如果都做到位，**绝大多数"低级错误"就能自动检出**——LLM 编造的引用、统计算错、不可复现的实验、循环论证。这块数学化是实打实可行的，而且是 AI 时代的巨大机会，因为**人类科学这些事都不做**。

### 3.2 不能数学化的部分（大概 30-40%）

| 判断类型 | 为什么不能 |
|---|---|
| **相关性** | 这个问题值不值得问？这是价值判断 |
| **品味** | 这个 framing 好不好？这是社会化训练的产物 |
| **"意义"** | 这个结果重要吗？需要外部参照系 |
| **隐藏假设** | 实验设计里没意识到的盲点，本身就不能从系统内找出 |
| **novelty** | 这个想法真的是新的吗？需要全人类知识作对照 |

这部分**结构上**不能数学化。不是工程问题，是哲学问题。

### 3.3 还有一层更深的限制：哥德尔式的

任何知识系统都不能在系统内部证明自己的完备性和一致性（哥德尔不完备定理的推广）。这意味着：

> **你永远需要一个外部参照系。**

- 对自然科学，外部参照系是**经验世界**（做实验）
- 对数学，是**公理的选择**（公理不能被证明，只能被选择）
- 对价值判断，是**价值系统的选择**（你不能从"是"推出"应该"）

所以即使把所有可数学化的部分都做完美，**"这是一篇好 survey 吗"这个问题永远需要外部判断**——要么是人类的价值系统，要么是显式给 AI 的目标函数。AI 不能自己产生"什么是重要"的判断，它只能执行你给的标准。

## 4. AI 时代到底怎么做

真实观点：**AI 时代的科研验证可能比人类时代更严格，而不是更弱**。原因是 AI 不受人类科研那几个结构性弱点的限制。

### 4.1 人类科学的结构性弱点

- 复现成本高 → 不做
- Peer review 时间稀缺 → 走过场
- 失败实验没地方发 → 知识流失
- PI 注意力有限 → 只能审 1-2 个学生
- 社会资本决定发表 → 不公平

### 4.2 AI 时代的对应机制

| 人类痛点 | AI 时代的对应机制 |
|---|---|
| 复现没人做 | **复现是 first-class 操作**，每次 claim 自动重跑 N 次 |
| Reviewer 走过场 | **N 个独立 agent 带不同 prior 互检**，每个 agent 都看全文 |
| 失败实验流失 | **失败的实验同等保存**，AI 可以查询"这试过吗" |
| PI 注意力有限 | **compute 即注意力**，可以审 10000 个分支 |
| 社会资本决定发表 | **有用性可计算**（下游节点能用到吗） |

不能解的几条：
- **"什么值得做"** → 永远是价值选择，必须显式给 AI
- **"这是好品味吗"** → 永远需要外部判断
- **隐藏假设** → 永远需要外部视角（多 agent 部分缓解）

### 4.3 四层架构

一个真正能"验证" AI 科研的系统，应该有四层，每层解决不同问题：

```
Layer 4: 价值层   ── "什么值得做"   （人给的目标函数，不可数学化）
Layer 3: 共识层   ── "领域怎么看"   （多 agent 带不同 prior 投票）
Layer 2: 验证层   ── "是否成立"     （复现、统计、逻辑，可数学化）
Layer 1: 证据层   ── "依赖什么"     （来源、依赖图、content-addressed）
```

**SciForge Evidence DAG 的位置**：主要在 Layer 1 和 Layer 2 的下沿。
- 做对了 Layer 1（content-addressed artifact + PROV）
- Layer 2 用 LLM-as-judge 蒙混过去了——本质上 Layer 2 没真做
- Layer 3 完全没做（多 agent 共识）
- Layer 4 假装不存在（把 PI 的判断隐式塞进 prompt）

> **真正缺的是 Layer 2 的真做（复现 + 统计校验 + 逻辑证明）和 Layer 3 的多 agent 共识。这两块是 AI 科研的核心机会。**

## 5. 回到具体场景：学生 survey 自己看不出问题

这件事在 AI 时代的解法**不是造一个超级 PI agent 去审 survey**（那是 SciForge 的方向，本质是把人类 PI 的局限复制到 AI 里）。

**而是把"审查"分解成多个可数学化的检查 + 多 agent 的独立判断**：

1. **每条引用是不是真的**——LLM 编造引用是确定的检查（DOI 解析、PDF 内容回查），不需要 PI
2. **每个统计是不是算对了**——可以重跑，不需要 PI
3. **每个 claim 的证据链完整吗**——依赖图可计算，不需要 PI
4. **N 个独立 agent 读完后能不能复述出同样的核心论点**——能测 narrative 一致性
5. **N 个独立 agent 带不同立场（赞成方/反对方/中立）能不能达成一致结论**——这是共识层

剩下的不能数学化的部分（"这值得写吗"、"写得好不好"），**老老实实承认需要人**——但需要的不是 PI 全能审阅，而是**人显式定义价值函数**："我希望这个 survey 满足 X、Y、Z 标准"。然后系统按 X、Y、Z 算。

> 这是**从"PI 作为黑箱审阅者"转向"PI 作为价值函数定义者"**。
>
> 前者不可规模化、不可验证、不可复用；后者全部可以。

## 6. 不舒服但真实的结论

> **能定下来的部分（60-70%），人类科学现在根本没定，所以光做这块就是巨大进步。**
>
> **不能定下来的部分（30-40%），是结构性的，永远需要外部判断。但"外部判断"不等于"PI 审阅"——可以是多个独立 agent、可以是显式价值函数、可以是下游使用反馈。**

人类科研的"严谨"在很大程度上是仪式。AI 科研的真正机会不是"模仿人类科研的仪式"，而是**把人类科研装作在做但实际没在做的事情真正做掉**——复现、统计校验、依赖图、失败实验保存、多视角共识。

> **PI 这个角色，作为"正确性保证者"是虚构的**（人类 PI 也保证不了正确性）。
>
> **作为"价值函数定义者"是真实的、不可替代的。**
>
> AI 时代不需要 PI 审阅每一份 survey，但需要有人定义"什么是好 survey"——这个定义本身就是科研品味，是真正的人类贡献。

## 7. 对 Axiom 的方向启发

如果认可上面这套思路，**Axiom 真正该做的不是 Evidence DAG（审计过去），而是 Layer 2 + Layer 3 的真东西**：

- **Layer 2**：每条 claim 的复现、统计校验、引用真实性——Axiom 的 Python 栈做这些比 SciForge 的 TS 栈强太多
- **Layer 3**：多 agent 互检——这恰好需要 Axiom 已经有的 `delegate` 子 agent 能力

这块不会叫 "Evidence DAG"，它会叫 **"Claim Verification Layer"**——重点在 *verify*，不在 *audit*。

Evidence DAG 解决"这个结论依赖哪些证据"（回顾性）。
Claim Verification Layer 解决"这个结论站得住吗、下一步怎么验证它"（前瞻性）。

前瞻性才是科研加速的核心。

## 附：与 SciForge Evidence DAG 的对比

| 维度 | SciForge Evidence DAG | Axiom 应做的方向 |
|---|---|---|
| 核心问题 | "这个结论依赖什么？" | "这个结论站得住吗？怎么进一步验证？" |
| 时间方向 | 回顾（audit past） | 前瞻（plan next） |
| NLI 实现 | LLM-as-judge | 真复现 + 统计校验 + 逻辑证明 |
| 失败实验 | 不保存（只记成功路径） | first-class citizen（金矿） |
| 多视角 | 单 verifier | 多 agent 带不同 prior 互检 |
| 下一步建议 | 不做 | 信息增益预测 + 最便宜反驳路径 |
| 目标用户 | PI 审阅 / 合规 | AI 自主科研的长期记忆 |
| 落地栈 | TypeScript（弱于科学计算） | Python（numpy/scipy/Biopython 直接可用） |

**不做 Evidence DAG 的"审计"部分**（NLI/reconcile/PROV/A0-A2）——那是给合规用的，AI 自己做科研时不需要。

**做"科研状态图"的"前瞻"部分**——这是 Axiom 的 Python 栈特别适合的、且 SciForge 完全没做的差异化机会。
